# The Cog Ladder — what this repo is for in the fleet

This document is written for the agent (human or machine) who boots this
repo next. It says what git-agent is becoming, what the corpus is, how to
extend it without breaking its witness status, and what would falsify the
central claim.

## The ladder

The fleet's cogs graduate through four levels:

| Level | Form | Cost at runtime | What carries the truth |
|-------|------|-----------------|------------------------|
| L0 | prompt + LLM | one expensive call per invocation | the model |
| L1 | CoT harvested → mock corpus | storage | the recorded oracle rows |
| L2 | tools for repeated sub-tasks | near zero | the tools + their pins |
| L3 | **repo = cog; LLM retained as simulator/oracle** | near zero | the equivalence pin vs the oracle |

git-agent is the fleet's **L3 reference home** — the one repo that already
owned all three substrate rungs: the fnv1a-64 hash-chained WAL
(`src/git_agent/quilt_emit.py`), the LLM seam (`src/git_agent/llm/mock.py`
behind `llm/base.py`), and FAIL-first pin culture
(`tests/test_quilt_provenance.py`).

## What the corpus is

`corpus/corpus.jsonl` is the fleet's first **L1 mock corpus**. Each row:

```json
{"id", "input": <vessel event>, "prompt": <the exact gate noul>,
 "output": {"kind": "substance", "value": <bool>},
 "oracle_source": "operator-label", "wal_ref": {...}, "synthetic": <bool>}
```

- `input` — a vessel event: either a capture from `tests/fixtures/` or a
  synthetic event generated by `tools/harvest_corpus.py` and pushed through
  the **real** `QuiltEmitter.ingest()` path (never a parallel writer).
- `prompt` — `jev_gate._VERIFIABLE_WORK_Q`, the same noul the production
  gate aims at judged events. The test asserts this, so corpus drift from
  the gate's actual question fails the pin.
- `output.value` — the oracle's verdict: does this event describe concrete,
  checkable engineering work?
- `wal_ref` — the chain position the input earned when ingested
  (`seq` + `hash`). fnv1a is deterministic, so re-running the harvester
  must reproduce identical hashes. Drift = the witness is not replayable.
- `oracle_source` — provenance of the verdict, ranked:
  `operator-label` (weakest; today's corpus) < `mock-seam` (recorded
  through the LLM seam) < `backend-transcript` (real decision-model
  scores, replayed). **The corpus self-promotes:** when real backend
  scores are recorded through the mock seam and the harvester is re-run,
  rows change source label — nothing else about the ladder moves.

## The equivalence claim

`src/git_agent/cogs/verifiable_work.py` is a deterministic rule cog
answering the verifiable-work noul without any backend. `tests/test_equivalence_seed.py`
pins the claim:

> On every corpus row, the cog's verdict equals the oracle's verdict.

That is the whole of L3 for this capability: **the repo is as good as the
call it replaces, witnessed on recorded inputs, replayable from the chain.**
Nothing more is claimed. Equivalence on N recorded rows is not equivalence
on the world; the corpus is the witness, not the truth.

## How to extend (without breaking witness status)

1. Add or capture a vessel event (fixture or synthetic).
2. **Label it**: assign the oracle verdict by hand only if you are the
   operator making the judgment; otherwise record it through the seam.
3. Re-run `python3 tools/harvest_corpus.py` — wal_refs regenerate
   deterministically.
4. If the cog now mismatches a row, the corpus wins and the cog loses:
   change the cog, never the label retroactively. (Retroactive label edits
   without a new oracle recording are witness tampering.)
5. `bash pin.sh` must end ALL PINS PASS before you push.

## What would falsify the claim

- A backend-transcript row the cog gets wrong (the real oracle disagrees
  with the rule on real recorded input) → the cog must be fixed or its
  domain narrowed.
- wal_ref drift on re-harvest (non-determinism crept into ingest) → the
  chain stopped being a witness.
- The corpus growing without oracle_source upgrades → the ladder is being
  gamed with cheap labels.

## Honest limits

- The corpus is small (~19 rows) and labels are operator-assigned. It
  demonstrates the mechanism; it does not yet certify the cog.
- Structural negative-controls (session_start/heartbeat/...) are labeled
  False by definition — they are not claims. They exist to stop the cog
  from hallucinating judgment where the gate never judges.
- The cog's "strong marker" rules are English-vocabulary heuristics. A
  worklog naming an artifact in another language or an obfuscated form
  will be misjudged until backend transcripts teach otherwise.
- The gate's real backend (TypeSafe Jev) has never run against this corpus;
  until it does, L3 for this capability is claimed, not yet demonstrated
  against the expensive iterator itself.
